# 33 · Distributed unique IDs — NOTES

> Pair: [`comprehension.md`](comprehension.md). Real `shopflow-id` (Snowflake/ULID/UUIDv7/Segment). Theme: **unique id bina coordination; aur id ka shape DB index ko affect karta.**

---

## KYA (one breath)
Har node ko unique id chahiye bina central sequence (bottleneck/SPOF). Aur **random id (UUIDv4) PK = DB bottleneck** (insert scatter, page split, cache miss); **time-ordered id = tail insert** (sasta). 4 generators, har ek alag trade-off.

## EASY WAY
> **"Random PK DB ko maarta (index bhar bikhre inserts). Time-ordered id tail pe rehta. Snowflake chhota+coordination, ULID/UUIDv7 no-coordination+128bit, Segment DB-block+not-sortable."**

## 4 GENERATORS (trade-off table)
| Gen | Size | Time-sortable? | Coordination | Throughput/limit | Note |
|-----|------|----------------|--------------|------------------|------|
| **Snowflake** | 64-bit | ✅ | **node id** (0..1023) | 4096/ms/node, ~69y | clock-backwards → **refuse**; seq exhaust → spin next ms |
| **ULID** | 128-bit (26-char base32) | ✅ (lexicographic) | **none** (80 rand bits) | — | same-ms → **suffix increment** (monotonic) |
| **UUIDv7** | 128-bit (standard UUID) | ✅ | **none** | — | drop-in jahan UUID chahiye (RFC 9562) |
| **Segment/Hi-Lo** | 64-bit | ✖ (per-gen seq) | **DB** | 1 DB hit per block | `UPDATE..RETURNING` block; restart=gap (OK) |

## SNOWFLAKE LAYOUT (yaad rakho)
```
[ 1 unused ][ 41-bit ms (custom epoch, ~69y) ][ 10-bit node (1024) ][ 12-bit seq (4096/ms) ]
  timestamp top = time-sortable (tail inserts)
  node = no coordination between generators
  seq  = 4096 ids/node/ms, exhaust -> spin to next ms (never reuse)
  clock BACKWARDS (NTP step) -> REFUSE (throw) : duplicate/time-travel se bachne ko
```

## KYU id-shape DB ko affect karta
```
 UUIDv4 (random) PK:  insert -> RANDOM leaf of B-tree -> page split, cache miss, write amp
    index > RAM hote hi hit-rate gir, write latency badhti (weeks mein, prod scale pe)
 Time-ordered (Snowflake/ULID/UUIDv7): insert -> TAIL (hot, cacheable) -> cheap
 => "unique hona kaafi nahi; LOCALITY key ke shape ka kaam hai." (topic 31 index-cliff cousin)
```

## DECISION (kaunsा kab)
| Chahiye | Lo |
|---------|-----|
| sabse chhota fast integer PK, high volume, node-id manage kar sakte | **Snowflake** |
| zero coordination + time-sortable, 128-bit OK | **ULID** (string) ya **UUIDv7** (standard UUID) |
| existing UUID columns/code | **UUIDv7** |
| internal high-write, id-order important nahi, cheap | **Segment** |
| externally-visible contiguous (invoice no.) | **DB sequence** (Segment gaps confuse) |

## NODE-ID ASSIGNMENT (Snowflake ka ops hazard)
- 2 live pods same node id → **collision**. Invariant: **koi 2 simultaneously-live generator ek node id share na kare.**
- Safe: **(a)** lease from etcd/ZK/DB (claim+renew, release on shutdown); **(b)** stable ordinal (StatefulSet pod ordinal / unique IP low-bits).

## GOTCHAS (interview)
- **Random PK = perf bug, cosmetic nahi** (scale/time pe dikhta).
- **Snowflake clock-backwards → refuse** (ya tiny drift pe wait), kabhi reuse nahi.
- **ULID same-ms monotonic** = suffix increment (fresh random nahi), warna same-ms out-of-order.
- **Segment gaps OK** (unique chahiye, gap-free nahi) par **not time-sortable**.
- **Central sequence** = bottleneck/SPOF at scale.

## UNDERSTANDING CHECK (khud bol)
1. UUIDv4 PK kyun bura? → *random → B-tree bhar scatter, page split/cache miss; time-ordered tail pe rehta.*
2. Snowflake backwards clock pe kya? → *refuse (throw) — duplicate/time-travel rok.*
3. ULID same-ms do ids ka order? → *suffix +1 (monotonic), lexicographic==creation order.*
4. Segment per-id DB cost? → *~0, block allocate (`UPDATE..RETURNING`) 1 hit per block; gap on restart.*
5. Orders ke liye kaunsा? → *UUIDv7 (time-sortable + no coordination + UUID-compatible); Snowflake ki 64-bit compactness chhodke.*

## INTERVIEW LINE
> *"Scale pe central sequence bottleneck, to coordination-free id — aur id ka **shape DB index affect karta**: random UUIDv4 PK inserts B-tree bhar bikhere (page split/cache miss), time-ordered tail pe. `shopflow-id`: **Snowflake** (64-bit 41ms+10node+12seq, 4096/ms/node, clock-backwards refuse, node-id chahiye), **ULID** (128-bit base32 sortable, no node-id, same-ms suffix-increment), **UUIDv7** (standard UUID time-ordered, drop-in), **Segment/Hi-Lo** (DB block `UPDATE..RETURNING`, dense, not time-sortable, gaps). Orders → UUIDv7."*
